# 面向课题组的文档资产管理与智能助理平台

## 数据库设计草案

## 1. 设计原则

- 使用 `PostgreSQL` 作为主数据库。
- 所有主键统一使用 `UUID`。
- 所有时间字段统一使用 `timestamptz`。
- 文档主记录、版本记录、流转记录、交接记录、审计记录分表存储。
- AI 结果与主业务事实分离，不直接写入主业务状态。
- 删除采用软删除，文件本体不因业务删除立即物理清理。

## 3. 核心表结构

### 3.1 users

用途：平台用户主表。

建议字段：

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | uuid | pk | 用户 ID |
| username | varchar(64) | unique, null | 登录名；管理员建号时填写，自助注册账号为 NULL |
| password_hash | varchar(255) | not null | 密码哈希 |
| display_name | varchar(64) | not null | 显示名称 |
| role | user_role | not null | 用户角色 |
| email | varchar(128) | null | 邮箱 |
| phone | varchar(32) | null | 手机号 |
| wechat | varchar(64) | null | 微信号 |
| status | varchar(16) | not null default `active` | 账号状态 |
| last_login_at | timestamptz | null | 最后登录时间 |
| created_at | timestamptz | not null | 创建时间 |
| updated_at | timestamptz | not null | 更新时间 |

索引建议：

- `idx_users_role`
- `idx_users_status`
- `idx_users_email_unique`：部分唯一索引 `UNIQUE (email) WHERE email IS NOT NULL`
- `idx_users_phone_unique`：部分唯一索引 `UNIQUE (phone) WHERE phone IS NOT NULL`

说明：

- `username` 自迁移 `010_self_registration.sql` 起允许为 NULL。Postgres 的 `UNIQUE` 约束视多个 `NULL` 为互不相同，因此自助注册用户（无用户名）不会互相冲突，老账号用户名登录不受影响。
- `email` / `phone` 仅在非空时强制唯一，不影响历史上联系方式为空的账号。

### 3.16 document_text_chunks（2026-11-10，迁移 014）

用途：文档当前版本正文的分块，供 AI 检索问答与全文检索共用。此前正文只存在 `assistant_requests.output` 的 JSON 里，无法检索。属于附属数据，可随时由重新抽取重建。

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | uuid | pk | 分块 ID |
| document_id | uuid | fk documents(id), not null | 文档 |
| version_id | uuid | fk document_versions(id), not null | 正文来源版本 |
| chunk_no | integer | not null | 块序号，从 0 开始 |
| content | text | not null | 正文片段 |
| created_at | timestamptz | not null | 写入时间 |

规则：

- 分块按字符计：每块 800 字，步长 700 字（相邻块重叠 100 字），单版本最多 400 块。
- 只索引文档的**当前版本**。新版本正文写入时整篇替换；旧版本的迟到抽取结果直接忽略。
- 写入时机：`document.extract_text` 或 `document.summarize` 结果回写时，在同一事务内写入。
- 迁移时从历史抽取结果回填当前版本的正文。

索引：`uq_document_text_chunks_version_chunk (version_id, chunk_no)`、`idx_document_text_chunks_document_id`；可用时建 `pg_trgm` GIN 索引 `idx_document_text_chunks_content_trgm`。扩展或索引创建失败只记 NOTICE，不阻断迁移，检索退化为顺序扫描。

向量检索说明：当前网关 `/v1/embeddings` 不可用、数据库镜像没有 pgvector，检索为词面匹配。本表是后续加入向量列的扩展位。

## 4. 关系说明

- 一个 `team_space` 下有多个 `projects`。
- 一个 `project` 下有多级 `folders`。
- 一个 `document` 属于一个 `project`，可挂接一个 `folder`。
- 一个 `document` 有多个 `document_versions`。
- 一个 `document` 有多条 `flow_records`。
- 一个 `document` 可被多个 `graduation_handover_items` 关联，但同一交接单中只能出现一次。
- 一个 `document`、`handover`、`project` 都可被 `assistant_suggestions` 关联。
- 一个 `assistant_conversation` 绑定单一 `scope_type + scope_id`。
- 一个 `assistant_conversation` 下有多条 `assistant_conversation_messages`。
- 一个 `assistant_request` 可选归属于一个 `assistant_conversation`。

## 5. 约束与触发逻辑建议

### 5.1 应用层事务

以下操作必须在单事务中完成：

- 上传新版本 + 更新 `documents.current_version_id` + 写审计事件
- 状态流转 + 更新当前责任人/状态 + 写流转记录 + 写审计事件
- 交接完成 + 批量更新文档责任人 + 写交接状态 + 写审计事件

### 5.2 建议的数据库检查约束

- `documents.is_archived = true` 时，`current_status` 应为 `archived`
- `documents.is_deleted = true` 时，`deleted_at` 不为空
- `document_versions.version_no > 0`
- `assistant_suggestions.confidence` 范围应在 `0` 到 `1`

### 5.3 不建议用数据库触发器承载业务

状态机规则、权限校验、AI 建议确认逻辑建议放在应用层，不建议用大量触发器实现。
