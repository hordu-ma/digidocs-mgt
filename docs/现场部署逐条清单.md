# DigiDocs 现场部署手册

适用于客户**首次部署**。DGX Spark 运行四个 Compose 服务及 HTTPS 入口，群晖提供文件存储与异机备份。现有客户环境的升级与回退见[运行说明](部署准备与运行说明.md)。每步达到“通过条件”再继续，失败时记录时间、步骤和脱敏后的错误。

## 1. 开工前确认

- [ ] 从交付负责人取得仓库访问权、**批准部署的 Git 提交号**、两台设备的地址、正式域名和证书、客户审批过的模型地址和模型名。通过公司密码库领取服务账号密码。
- [ ] 在 DGX 上用交付运维账号确认 `git --version`、`docker compose version`、`docker info`、`nginx -v`、`make --version`、`openssl version` 均可运行。Compose 须支持 `up --wait`。已有站点时由客户 IT 确认 80/443 配置与防火墙。
- [ ] 在群晖 DSM 创建专用共享目录和服务账号，给该目录读写、创建和删除权限，启用 File Station。由客户 IT 配好快照与 DSM TLS，证书须与配置的 NAS 主机名匹配，DGX 及应用容器须信任证书链。
- [ ] 约定交付范围、测试项目和账号、恢复时间与允许丢失的数据窗口。若需迁移旧库或接管已有部署，先走升级与备份流程。

**通过条件**：负责人提供批准版本和配置值，DGX 可以访问 Git、构建镜像仓库、群晖 HTTPS 和选定模型入口。

## 2. 在 DGX 准备配置

使用团队提供的仓库地址拉取代码，将仓库目录命名为 `digidocs-mgt`，以匹配备份脚本默认的 Compose 卷名。进入该目录并执行以下命令。将尖括号内占位文字换成实际值。

```bash
git checkout --detach <批准的提交号>
git rev-parse HEAD
umask 077
cp -n .env.production.example .env
chmod 600 .env
nano .env
```

| 配置 | 填写方法 |
| --- | --- |
| `POSTGRES_PASSWORD`、`DATABASE_URL` | 用 `openssl rand -hex 32` 生成数据库密码，将两个字段中的密码改成同一个值。主机名保持 `postgres:5432`，保留模板的数据库名及用户名。 |
| `JWT_SECRET` | 再运行一次 `openssl rand -hex 32`，填入独立值。 |
| `WORKER_CALLBACK_TOKEN`、`CALLBACK_TOKEN` | 再生成一个随机值，填入两处。回调地址保持 `http://backend-go:8080`。 |
| `SYNOLOGY_HOST`、`SYNOLOGY_PORT`、`SYNOLOGY_ACCOUNT`、`SYNOLOGY_PASSWORD`、`SYNOLOGY_SHARE_PATH` | 按客户配置填写。共享路径如 `/DigiDocs`。保持 `STORAGE_BACKEND=synology`、`SYNOLOGY_HTTPS=true`、`SYNOLOGY_INSECURE_SKIP_VERIFY=false`。 |
| `OPENCLAW_BASE_URL`、`OPENCLAW_API_KEY`、`OPENCLAW_MODEL` | 填写批准的 OpenAI 兼容网关、凭据和模型标识。基础地址以 `/v1` 之前的部分为准。同机服务使用容器可达地址，核验网关在容器网络可访问。 |
| `PUBLIC_BASE_URL`、`CORS_ALLOW_ORIGINS` | 填写同一个正式 HTTPS 地址，例如 `https://docs.example.org`，末尾去掉斜杠。按下文的单层入口配置另加一行 `TRUSTED_PROXY_DEPTH=2`。 |
| `SELF_REGISTRATION` | 保持 `invite_only`，或按客户要求设为 `closed`。 |
| `EMBEDDING_BASE_URL` | 合同包含语义检索时填写客户批准的容器可达嵌入端点并核对模型。留空启用关键词检索。 |

三个宿主机映射保持 `127.0.0.1:15432`、`127.0.0.1:18081`、`127.0.0.1:18080`。秘密直接填入受限文件，向交付账本记录密码库条目名称。

```bash
docker compose --profile app config --quiet
docker compose --profile app up -d --build --wait --wait-timeout 180
docker compose --profile app ps
make post-deploy-check
```

**通过条件**：四个服务均 `healthy`，检查脚本全为 `[OK]`，迁移清单一致。此时尚未对客户开放入口。

## 3. 创建首个管理员

仅对**全新空库**执行。先确认站点尚未对外转发，再在 DGX 上执行计数。结果应为 `0`。

```bash
docker compose exec -T postgres sh -c \
  'psql -X -At -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "SELECT count(*) FROM users"'
```

临时启动开放注册。用 SSH 本地转发（在同事电脑上运行 `ssh -N -L 18080:127.0.0.1:18080 <运维用户>@<DGX地址>`），打开 `http://127.0.0.1:18080/register`，用公司为本客户指定的管理员邮箱和独立口令注册。

```bash
SELF_REGISTRATION=open docker compose --profile app up -d --wait --no-deps backend-go
```

注册后立即恢复 `.env` 的注册模式，再执行一次性角色设置。该语句只会在库中恰有一个用户且邮箱匹配时更新。

```bash
docker compose --profile app up -d --wait --no-deps backend-go
read -r -p '刚注册的管理员邮箱: ' admin_email
docker compose exec -T -e "FIRST_ADMIN_EMAIL=$admin_email" postgres sh -c \
  'psql -X -v ON_ERROR_STOP=1 -v "first_admin_email=$FIRST_ADMIN_EMAIL" -U "$POSTGRES_USER" -d "$POSTGRES_DB"' <<'SQL'
UPDATE users SET role = 'admin', updated_at = NOW()
WHERE email = :'first_admin_email' AND role = 'member'
  AND (SELECT count(*) FROM users) = 1
RETURNING email, role;
SQL
unset admin_email
```

**通过条件**：显示 `UPDATE 1` 和 `admin`。退出后重新登录，在管理页创建真实团队、项目和负责人的账号。生产库使用正式账号，演示种子数据在隔离环境使用。若计数或更新结果不符，保持正式注册模式并联系交付负责人。

## 4. 开通正式 HTTPS 入口

由客户 IT 确认域名指向 DGX、证书有效、80 转向 443，443 代理到 `127.0.0.1:18080`。使用[运行说明中的 Nginx 样例](部署准备与运行说明.md#https-入口样例)，先 `sudo nginx -t`，成功后再 `sudo systemctl reload nginx`。

```bash
PUBLIC_URL=https://docs.example.org make post-deploy-check
```

- [ ] 从一台客户电脑打开实际 HTTPS 地址，确认浏览器信任证书；HTTP 地址须跳转。
- [ ] 从该电脑确认 18080、18081 和 15432 不对用户开放。群晖 DSM 只向授权网段和运维人员开放。

## 5. 用客户入口验收

| 谁操作 | 做什么 | 通过条件 |
| --- | --- | --- |
| 管理员 | 创建团队、课题、负责人和普通成员 | 用户角色、项目成员身份和注册模式符合交付约定 |
| 项目成员 | 上传样例文档，再用同一文件名上传不同内容；分别下载 | 两个版本下载结果分别等于原文件；查看、预览及下载能查到审计 |
| 其他项目成员 | 用自己的账号尝试访问该项目和文档 | 界面无法看到资源，打开授权测试用的文档链接时请求被拒 |
| 负责人、接收人 | 归档、解档；按角色发起和确认交接 | 归档时新版本受拒，已确认清单不能改写 |
| 项目成员、仓库负责人 | 在样例仓库推送并核对同步记录，轮换令牌再验证 | 新凭据可用、旧凭据失效；若页面复制出 HTTP 地址，改用相同路径的正式 HTTPS 地址 |
| 获准使用 AI 的成员 | 在 DocsAgent 询问样例文档内容，核对摘要与引用 | 正常完成，引用指向正确材料；合同包含语义检索时用同义改写验证召回 |
| 运维 | 按约定文件上限测试上传、断线与重新提交 | 记录用时、错误提示和最终文件摘要；重试验收以实际结果为准 |

记录执行人、测试时间、URL、版本、结果和证据路径。用测试数据的自动烟测在隔离栈运行，命令为 `make smoke-e2e`。

## 6. 备份与签收

```bash
sudo loginctl enable-linger "$USER"
./scripts/codex/install-backup-timer.sh
systemctl --user start digidocs-backup.service
systemctl --user list-timers digidocs-backup.timer
journalctl --user -u digidocs-backup.service -n 30 --no-pager
```

- [ ] 首次备份显示数据库、Git 卷和群晖异机副本验证成功。单独把 `.env` 存入客户批准的密钥库。
- [ ] 利用隔离环境演练恢复 PostgreSQL、Git 裸仓库与 NAS 快照。核对文档、历史版本、项目权限和 Git 克隆。记录恢复点及耗时。操作方法见[运行说明](部署准备与运行说明.md#备份和恢复)。
- [ ] 交接记录包含运行镜像 ID、部署版本、域名、备份位置、值班人和未通过事项。现场负责人按[优化验收清单](客户交付优化清单.md)确认结果后签收。
